# Agent Responsibility Matrix

Generated by **forge-team-builder** as Step 4b of the forge playbook. This document
maps every feature in [`docs/features/`](./features/) and every cross-cutting concern
to its **primary owner agent** and **collaborating agents** under
[`.github/agents/`](../.github/agents/).

---

## Validation results

| # | Check | Result | Notes |
|---|-------|--------|-------|
| 1 | Every feature in `docs/features/` maps to exactly one primary owner agent | ✅ Pass | All 12 feature documents have a single, unambiguous owner (1:1 mapping; see matrix below). |
| 2 | No ownership gaps (every FR/NFR has an owner) | ✅ Pass | All twelve feature areas (PROV, ENRICH, STORE, SINK, CLOUD, STREAM, ALERT, WEBUI, REDACT, ANALYZE, SUMM, PLUGIN) and all NFRs (coverage NF-04, strict-mode NF-05, WCAG, secret-scanning, release-blocker gates) are owned. |
| 3 | No two agents have conflicting / overlapping primary responsibilities | ✅ Pass | Each feature area has exactly one primary owner. Adjacent agents have explicit handoff contracts (Provider → Enrichment → Redaction → Datastore → Sink/Streaming/Analyzer). Cross-cutting agents (QA, Release Manager) are scoped to verification & shipping respectively and do not own feature code. |
| 4 | Cross-cutting concerns (security, accessibility, observability, release) have explicit owners | ✅ Pass | Security/privacy → `redaction-engineer` (+ `qa-engineer` for secret-scanning enforcement). Accessibility → `web-ui-engineer` (WCAG 2.1 AA) + `qa-engineer` (axe-core gates). Observability/alerts → `observability-engineer`. Release/versioning/ADRs → `release-manager`. |

**Issues flagged:** _No issues found._

Notes on meta-agents not in the matrix: `forge-team-builder` and `project-orchestrator`
are workflow/meta agents (team generation and orchestration). They do not own product
features and are intentionally excluded from the feature/cross-cutting ownership matrix.
